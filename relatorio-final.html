3. Descrição do projeto

A Balsas Experience API disponibiliza informações estruturadas sobre atrações turísticas de Balsas, Maranhão. Aplicativos, páginas web e clientes HTTP podem consultar locais históricos, opções de lazer e experiências de natureza e aventura, com descrição, localização, categoria, tags e distância do centro quando conhecida.

A API atende quem precisa integrar essas informações a uma interface sem acessar diretamente arquivos ou tabelas. Além da listagem e dos filtros por categoria, tag e texto, oferece operações para cadastrar, atualizar e remover atrações, registrar avaliações e consultar categorias com contagem de atrações. O PostgreSQL mantém os dados entre reinicializações do servidor.

5. Modelo de dados

TabelaCamposRelações
Categoriaid, nome únicoUma categoria classifica várias atrações.
Atracaoid, nome, descricao, cidade, estado, distanciaCentroKm opcional, criadaEm, categoriaIdPertence a uma categoria; relaciona-se a várias tags e avaliações.
Tagid, nome únicoRelação muitos-para-muitos com atrações por meio de _AtracaoToTag.
Avaliacaoid, visitante, nota, comentario opcional, criadaEm, atracaoIdPertence a uma atração; exclusão da atração remove avaliações relacionadas.

As tags são uma tabela separada porque várias atrações podem compartilhar uma tag e cada atração pode ter várias tags; a tabela de ligação representa essa relação sem armazenar arrays ou repetir nomes nos registros.

7. Como executar o projeto

  1. Clone o repositório e entre na pasta:
git clone https://github.com/hpseven7-00/balsas_experience.git
cd balsas_experience
npm ci
  1. Crie um banco PostgreSQL e copie .env.example para .env. No arquivo local, configure a connection string do seu banco:
DATABASE_URL="postgresql://USUARIO:SENHA@HOST/neondb?sslmode=require"

Use credenciais próprias, mantenha o arquivo .env fora do Git e nunca compartilhe sua senha.

  1. Aplique as migrações existentes e gere o cliente:
npm run build
  1. Popule o banco de desenvolvimento e inicie a API:
npm run seed
npm run dev

A API local ficará em http://localhost:3000. O seed apaga os registros antes de inserir os dados de exemplo; execute somente em banco vazio ou descartável.

10. Dificuldades e aprendizados

O projeto substitui o armazenamento temporário em JSON por um modelo relacional. Uma decisão importante foi representar tags em uma relação muitos-para-muitos, usando tabela de ligação, em vez de guardar uma lista dentro da atração. O Prisma simplifica essa relação no código, mas o schema e as migrações deixam explícita a estrutura criada no PostgreSQL.

Na escrita, connectOrCreate reaproveita categorias e tags sem duplicá-las; no PUT, as tags anteriores precisam ser desligadas para que a operação realmente substitua o recurso. A avaliação também exige validar a nota antes de gravar e traduzir o erro de registro inexistente do Prisma para o status HTTP 404.
